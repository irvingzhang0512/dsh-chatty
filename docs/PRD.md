## 1. 产品定位与本次原则

**以 DSH 官方语音输入为基础，由 dsh-chatty 集中提供持续听写、云端识别、语音指令、草稿处理、回复朗读和语音对话。**

本版按以下含义落实用户的两项要求：

1. **基于原有插件优化。** 官方已有的识别服务、SenseVoice 本地识别、模型准备、录音校验、原生输入框及安全插入规则作为基础；新增能力接入这套体系。已有交互存在扩展点时复用；缺少扩展点时先验证接入方案，不假定官方已经支持持续监听或流式识别。
2. **其他功能全部集成在 dsh-chatty。** 云端 Provider 适配、持续采集与分句、流式扩展、口令、润色、TTS、朗读策略、模式控制及增强设置均由同一个 `@irvingzhang0512/dsh-chatty` 包交付。官方基础包仍是上游依赖，不另拆自研语音插件。

“集成在一个插件”指增强能力的交付与操作入口统一；官方识别偏好、模型缓存、DSH 凭据和会话草稿仍由各自原有所有者保存。界面统一不意味着复制这些数据。

## 2. 为什么要优化

官方语音输入已经覆盖短录音转文字：用户开始录音，停止后识别，文字插入输入框，再检查并发送。现有 dsh-chatty 扩展了长语音与朗读，但另外维护采集、Provider 选择和语音文本缓冲，与官方链路尚未接通。

本次重点解决四个问题：

- 短录音与长听写共享识别服务和语言选择，用户能看清音频在本地还是云端处理。
- 语音与键盘编辑共用原生输入框，识别、撤销、润色不能覆盖无关手写内容。
- 听写、发送、回复朗读的行为按模式明确，避免普通发送后旧语音内容被再次写回。
- 语音增强功能集中配置，能看懂准备、录音、识别、播放和失败分别处于哪一步。

## 5. 用户流程与模式

### 5.1 一次听写

开始录音 → 说话 → 停止并识别 → 插入原生输入框 → 检查／修改 → 手动发送。

- 默认沿用已有官方识别服务与语言选择，不因安装 Chatty 擅自切换。
- 取消丢弃本次录音；停止保留录音并识别。已有草稿均不被清空。
- 录音开始时捕获会话、Provider、语言和插入位置。草稿版本变化导致自动插入失败时，保留文字供显式插入或丢弃。
- 普通听写默认手动发送；已有显式自动发送配置若继续保留，必须显示“说完自动发送”，迁移时不得悄悄开启。

### 5.2 持续听写

选择持续听写 → 开始 → 每句识别并累计 → 检查／撤销／润色 → 发送 → 继续下一段或停止。

- 停顿只结束当前句，监听仍持续；一次有声片段只产生一个正式结果。
- 没有原生流式能力的识别器采用分句后识别；识别完成前的预览不进入正式草稿，也不触发口令。
- 普通发送、语音发送和插件按钮发送都必须使已发送内容退出待发送状态；下一句不带回旧内容。
- 句长、音频大小和排队数量受有效上限约束，不能无限积累。达到限制需反馈并按已确认分句策略收尾，不改用其他 Provider。
- 撤销仅处理可追溯语音插入；区间已被手动编辑时，保留草稿并提示使用编辑器撤销。清空也不得删除无关手写内容。

### 5.3 语音指令与润色

最终识别文字 → 判断是否为已启用的整句口令 → 执行动作或插入正文。

- 7 类动作沿用现有范围；不新增独立取消、暂停／继续口令。
- “这个请求发送以后要等回复”作为正文；“发送”在口令开启时触发发送；前缀模式下需说“DSH，发送”。
- 润色默认作用于可追溯语音文本，不顺带改写手写内容；结果回写前检查草稿版本，失败或冲突保留原草稿，并展示可选结果。
- 润色与语音摘要只按用户启用的策略调用模型，界面解释作用范围；润色成功不会隐含发送。

### 5.4 回复朗读

用户点击朗读，或启用自动朗读 → 整理回复内容 → 分段合成 → 顺序播放 → 可随时停止。

- 保留页面原始回复，播放队列只包含适合听的内容。
- 代码默认跳过，可有提示；表格与长列表按策略摘要；链接只读文字。
- 手动朗读沿用“最新助手回复”，本版不承诺每条历史消息都有独立朗读按钮。
- 停止、取消轮次、切换会话或关闭模式后，在途音频不能重新入队播放。
- 检测人声打断时先停播再进入识别；是否能稳定避免误打断需真实扬声器／耳机验证。

### 5.5 语音对话

显式开启语音对话 → 说完自动发送 → 助手回复自动朗读 → 继续下一句。

- 模式提示持续显示“说完自动发送”，普通听写不因模式退出后继续自动发送。
- 模式属于当前会话；切换会话停止当前监听与播放，迟到文字不写入新会话。
- 关闭后停止模式拥有的监听与播放，未发送文字保留；不会改写用户持久化的自动朗读偏好。
- 助手运行中或输入锁定时，识别文字进入待处理状态；不绕过原生提交限制。自动提交的具体队列规则须在实施契约中固定。

## 6. 界面与配置要求

产品目标是在原生输入区提供一个清楚的语音入口，区分一次听写、持续听写和语音对话，并提供朗读／停止。日常操作使用中文动作与状态；详细口令、识别预览及错误在展开区域显示。

统一设置按用户目的分组：

| 分组 | 用户可调整内容 | 数据所有者 |
|---|---|---|
| 识别 | 本地／云端服务、支持的语言、模型准备及准备进度 | 官方识别服务与 Provider；云端参数由 Chatty |
| 录音 | 默认设备、分句灵敏度、静音时长、句首缓冲、音频处理 | 原生设备偏好或 Chatty 扩展，按版本能力接入 |
| 草稿与口令 | 自动发送提示、口令模式与词表、润色策略 | Chatty；正文由原生编辑器 |
| 朗读 | Provider、音色、语速、音量、自动朗读、打断及内容策略 | Chatty |
| 连接与凭据 | 凭据引用、配置状态、错误及重试入口 | DSH Credentials 保存密钥；Chatty 只展示状态 |

不要求用户在官方与 Chatty 两处维护同一份识别偏好。新增可配置项需同时交付界面；已有高级字段的保留、迁移和失效清理由配置契约逐项说明。原生界面缺少公开增强入口时，本目标需要先完成组合方案验证，不能用私有状态或 DOM 劫持宣称已接入。

## 7. 本版范围与边界

**本版建议范围**：官方语音基础接入、本地／云端统一识别、持续听写与能力明确的预览、原生草稿安全编辑、现有 7 类口令、可选润色、回复整理与 TTS、显式语音对话、统一设置及旧配置迁移。

以下能力继续保留为历史规划，本版不纳入开发：声学唤醒引擎、完整 AEC、真正双向实时语音、Speech-to-Speech 模型、说话人识别、多人声源区分、本地 TTS、翻译、跨应用控制及会议纪要自动生成。真实波形仍为 F010 待确认事项，本版先沿用音量柱。

本地 STT 的变化仅指复用官方 SenseVoice，归入 F013；不自建另一个本地模型下载与推理体系。用户笔记中的文件大小对照不能当作摘要校验或真人转写成功证据。

## 8. 验收重点

| 场景 | 必须观察到的结果 |
|---|---|
| 既有官方本地识别已经就绪 | Chatty 读取同一 Provider 和准备状态，不要求重复下载，不自动上传到云端 |
| 草稿先有手写内容，再录一段 | 在有效位置插入一次，手写内容保留；草稿已变化则保留识别文字供选择 |
| 持续说三句，手动发送后再说一句 | 三句按序累计一次；下一句不带回已发送内容 |
| 识别句包含口令词 | 仅整句命令触发；partial、重复 final 和迟到结果均不能重复执行 |
| 输入框编辑中请求润色，随后再手动修改 | 冲突不覆盖新编辑，原草稿与润色结果可辨认 |
| 选中本地识别后识别失败 | 显示可处理错误，音频不自动改发云端；取消后停止任务 |
| 切换会话或关闭语音对话 | 麦克风与播放释放，旧识别和音频不进入新会话 |
| 回复包含代码、表格、链接 | 页面内容完整；朗读符合配置且分段有序；停止后旧音频不再播放 |
| 使用旧配置进入新版 | 先有迁移预览与备份；有效配置保留，确定失效字段清理，无关与未知字段不丢失 |

详细验收及证据映射保留在 SPEC，避免本 PRD 重复铺开模块导出、HTTP 路由和测试细节。

## 9. 开发前仍需固定的接入事项

1. **统一入口**：目前核对的官方 UI 公开声明没有录音结果拦截或持续采集的扩展接口。需在目标 0.2.0-rc.2 验证可用 Slot／组合方式，再确认如何保持一个入口、一个麦克风所有者；不把未知 Hook 写成可用 API。
2. **流式能力**：官方服务只接受完整录音。需固定 Chatty 流式扩展的请求、事件、取消、上限和同 Provider 回退契约，并真服务核验火山中间结果；缺少证据时只承诺最终转写。
3. **编辑器与提交**：需核对目标版公开输入 API，固定语音区间撤销、润色回写、普通发送通知与锁定时待处理规则。没有可靠公开能力的操作应给出替代方案供确认。
4. **迁移**：需从脱敏的真实旧配置确认 Provider id 映射、语言映射、设备偏好与失效字段引用，再固定可回滚迁移。

本版可先确认产品范围与行为原则；以上事项补齐为可实施契约后，再确认新增语义并进入源码开发。旧的 [DSH 升级契约](DSH-UPGRADE-20261011.md) 与本版共享宿主适配前提，不作为本版已获确认的依据。
